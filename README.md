# alu_uvm_env - UVM verification environment for a parameterised ALU (executed, measured)

A self-checking UVM environment, with sequences, a driver, a monitor, a scoreboard with an independent reference model and a covergroup,
around a small registered ALU (ADD, SUB, AND, OR, XOR; operand width set at compile time; one cycle of latency).

> **Portfolio copy (2026-10-21).** My original repository says the environment "was written and reviewed without execution", because I
> didn't have a UVM-capable simulator at the time. In this copy it **has been run**, on Verilator 5.052 with the Accellera UVM library
> (antmicro `uvm-verilator`, IEEE 1800.2-2017). The original sources (`Design/`, `Verification/` and the design spec in `docs/superpowers/specs/`) are unchanged, and
> everything I added is in `scripts/`, `ext/`, `results/` and `docs/portfolio/`. The working plan I built the environment from isn't kept in this folder. The original README is reproduced, unchanged, at the end
> of this file.

## Reproduce

```bash
scripts/setup_toolchain.sh                      # one time: Verilator v5.052 + uvm-verilator into ../../_toolchain
scripts/run_uvm.sh build/w8                     # WIDTH 8, exhaustive_seq: 5 opcodes x 256 x 256 + 25 corner-case items
scripts/run_uvm.sh build/w16 --width 16 --ext ext/uvm_ext.sv --plus +uvm_set_type_override=random_seq,random_seq_vl
python3 scripts/cov_uvm.py build/w8/coverage.dat              # covergroup bins from the simulator's coverage data
python3 scripts/mutate_alu.py                   # 14 injected bugs vs the original environment
python3 scripts/mutate_alu.py --with-ext        # the same 14 with ext/uvm_ext.sv (closes the reserved-opcode gap)
```

## Tool limits I ran into (Verilator 5.052) and what I did about them

| Limit | Handling |
|---|---|
| `covergroup.get_coverage()` returns 0.00 % | the covergroup *is* sampled (its bin hits are written to `coverage.dat`), so `scripts/cov_uvm.py` computes the figure from the bin data |
| `ignore_bins` isn't applied to the recorded bins | the script leaves out the bins that `coverage.sv` declares ignored, and prints the raw figure as well |
| the constraint solver rejects `dist` weights and `opcode inside {package parameters}`, so `randomize()` returns 0 | `ext/uvm_ext.sv` provides `random_seq_vl` (procedural generation), selected with a UVM factory type override, so the original sources aren't edited |
| the stock `uvm_dpi.cc` needs a vendor HDL back-door | three small wrappers in `scripts/dpi_wrappers/` compile the command-line, regex and report helpers, and HDL back-door access is compiled out |

## Not covered

There are no assertions on the DUT, no UVM register model, and no synthesis or timing run (the block is only a verification vehicle). The
monitor doesn't observe reset values, which is why mutants A08 and A14 survive, and the original `random_seq` can't run on this simulator.
`docs/portfolio/alu_uvm_design_document.pdf` has the full write-up.

# Original README (unchanged, as received)

## Parameterized ALU

A fixed-1-cycle-latency ALU (ADD/SUB/AND/OR/XOR) with a compile-time
parameterized operand/result width, verified with a self-checking UVM 1.2
testbench.

## Design

`Design/alu.v` accepts one instruction (`opcode`, `num1`, `num2`) every
clock cycle with no handshake, and produces the registered `result`/
`carry_out` for that instruction exactly one cycle later. ADD and SUB
share one adder (`num2` conditionally inverted, subtract fed in as
carry-in). Opcodes `3'b101`-`3'b111` are reserved and drive `result`/
`carry_out` to 0.

| opcode | operation |
|--------|-----------|
| `000`  | ADD |
| `001`  | SUB |
| `010`  | AND |
| `011`  | OR  |
| `100`  | XOR |

## Verification

`Verification/` is a UVM 1.2 environment: `sequence -> sequencer ->
driver -> DUT`, and `DUT -> monitor -> scoreboard` / `monitor ->
coverage`. Because the DUT's result lags its instruction by one cycle,
the monitor re-pairs each result with the instruction that produced it
before publishing a transaction, so the scoreboard can stay a stateless
comparator with an independently-derived expected-value model.

Coverage uses width-relative value-class bins (`zero`/`low`/`high`/
`max`) crossed with opcode, so it stays meaningful at any configured
`WIDTH` (set in `Verification/alu_pkg.sv`). `Verification/test.sv` runs
an exhaustive sequence for `WIDTH <= 8`, and a coverage-driven random
sequence above that.

## Running this

This environment was written and reviewed without execution — see
`docs/superpowers/specs/2026-09-28-parameterized-alu-uvm-design.md` for
why (no UVM-capable simulator was available in the environment this was
built in). It targets standard UVM 1.2 and needs a SystemVerilog
simulator with a UVM library (Questa, VCS, Xcelium, or a UVM-capable
Verilator build) — compile `Design/alu.v` alongside `Verification/testbench.sv`
(the DUT module isn't pulled in by `` `include ``) and point the simulator at
`Verification/testbench.sv` as the top-level module (`alu_tb_top`).
